# KAT500 implementation plan

Goal: deliver the approved KAT500 applet and Advanced tools on Mac and echo-ms300prd, using direct serial and raw TCP, tested without RF transmission.
Architecture: a dedicated libaethercore protocol/maintenance implementation and models/Kat500Model facade consumed by CanonApplet and Peripherals. QObject timers on the owner thread, no new thread or dependency. Existing KPA500 remains unchanged.
Tech stack: C++20, Qt 6.12, existing Qt SerialPort/Network/Widgets, CTest, native Mac and Windows.
Spec: ../specs/2026-10-13-kat500.md. Research authority: /Users/ozy/Documents/AetherSDR/elecraft-rea/kat500-investigation/{runtime-findings.md,public-feature-matrix.md,help-complete.txt} and retained official reference/captured synthetic wire.

## Global constraints

- No firmware updater, firmware download/check/flash/recovery, raw Command Tester, or macros. Installed RV identity and official Utility/help links remain.
- No physical RF transmission, radio TUNE/MOX/PTT or tuner tune. Automation testing must keep TX permission off. Flex 6700 connection authorized. KAT500 bridge 100.100.216.93:4001; KPA500 :4004; echo-ms300prd via ozy SSH. User authorizes stopping bridge temporarily to release COM ports, restoring it afterwards.
- Latest user authorization expands earlier design's read-only hardware boundary to reversible non-TX controls/configuration tests with before-state and restoration. Erase/reset/restore destructive paths use socket-free injected transport fixtures, not real memories.
- GUI includes models/Kat500Model.h and model-owned value types, not new core connection headers. No radio-family branches or raw radio wire commands above the seam. Tuner wire remains in core.
- Radio/tuner state is authoritative. Unknown and stale are not OFF. SET requests require readback; reconnect never replays mutations. EEPROM writes require fresh idle/no-RF identity checks and stop on uncertainty; no automatic retries/reboot/power-on.
- Client-owned preferences use feature JSON/AppSettings. Device config is not persisted or replayed by AetherSDR.
- KT500 visible only after identity, retained while same transport open even off/silent; hidden when transport closes. Model change signals drive it.
- Mini retains operating controls/status from supplied screenshot. Match KPA500 colors and compact scrollable geometry; ThemeManager tokens only.
- Tests in tests/tests.cmake; no new default synthetic firmware socket peer. Use injected transport tests. User docs same branch, no CHANGELOG edit.
- No GitHub pushes or merge in implementation tasks. Signed local commits under Ozy311 identity; parent owns publication/deployment. Issue #4953 claimed by parent. Base is KPA500 #5991 head 43a7a61fa2294b84cec11af8481c855138b13b16.

## Review focus

Sleep wake handshake and first-character loss; combined/chunked/overflow input; case-sensitive boot identity; late/unsolicited replies vs operation matching; DM compound rows must not update live status. SET acknowledgment versus confirmed readback. Busy/disconnect/identity-change lifetimes; no pending mutation replay. Backup complete coverage/checksum/native format, exact restore regions excluding faults and identity, partial failures and verification. Native file dialogs must be nonblocking and survive closing parent. VFWD/VRFL are ADC counts, not watts. UI unavailable reasons and hidden applet rules; no inadvertent tune from connection or following frequency.
